# Практический отчет: сокращение числа каналов EMG для gesture classification

## 1. Цель работы

Целью работы было проверить, можно ли сократить число EMG-каналов в задаче распознавания жестов без неприемлемой потери качества и при этом сохранить корректность офлайн-оценки. Практический интерес состоит в том, что уменьшение числа каналов потенциально упрощает аппаратную часть, снижает размер признакового вектора и делает систему более пригодной для компактного носимого устройства.

В ходе работы решались три связанные задачи. Во-первых, нужно было проверить, нет ли утечки тестовой выборки в процедуре отбора каналов. Во-вторых, требовалось количественно оценить компромисс между качеством и числом каналов в диапазоне `24 -> 16 -> 12 -> 8 -> 6 -> 3`. В-третьих, нужно было сравнить несколько вариантов построения признаков и сделать выводы, какие конфигурации можно использовать в дальнейшем как рабочие, а какие пока стоит рассматривать только как исследовательские.

## 2. Экспериментальный pipeline

Использовался следующий pipeline:

```text
raw EMG -> optional filtering -> sliding window -> TD-features -> LDA -> metrics
```

Основные компоненты эксперимента:

- датасет: `GRABMyo`;
- жесты: `WF`, `WE`, `HO`, `HC`;
- классификатор: `LinearDiscriminantAnalysis`;
- базовые time-domain признаки: `MAV`, `RMS`, `WL`, `ZC`;
- расширенный набор TD-признаков: `SSC`, `VAR`, `IEMG`, `WAMP`, `AAC`, `DASDV`, `LOG`;
- метрики: `accuracy`, `macro_f1`, `processing_time_ms`, `feature_vector_size`.

Ключевой метрикой для выбора конфигураций считался `Macro-F1`, потому что она лучше отражает баланс по всем четырем классам, чем одна только accuracy.

## 3. Валидационный протокол и контроль test leakage

Главной методологической проблемой в ранней версии экспериментов было то, что ranking и greedy использовали test split для выбора каналов. Это давало завышенную оценку качества и делало результаты непригодными как строгий аргумент в отчете.

После исправления использовалась leakage-safe схема:

```text
selection_train -> selection_val -> final_train -> final_test
```

Интерпретация этапов:

- `selection_train` использовался для обучения моделей внутри процедуры выбора каналов;
- `selection_val` использовался только для сравнения candidate channel sets;
- `final_train = selection_train + selection_val` использовался для финального обучения LDA с уже фиксированным набором каналов;
- `final_test` использовался только для финальной оценки.

Проверка по CSV показала, что во всех новых артефактах поле `selection_uses_test` имеет значение `false`:

- `channel_sweep_results.csv`
- `channel_sweep_medium_results.csv`
- `channel_sweep_full_results.csv`
- `feature_sweep_results.csv`
- `feature_sweep_medium_results.csv`
- `feature_sweep_medium_full_results.csv`
- `feature_sweep_medium_ranking_results.csv`
- `channel_sweep_filtered_comparison.csv`

Следовательно, итоговые выводы ниже опираются уже на leakage-safe результаты, а не на старые quick-оценки.

## 4. Baseline для полного набора каналов

В роли baseline использовалась конфигурация `24 channels + basic TD features + raw signal`. На полном leakage-safe split (`channel_sweep_full_results.csv`) она дала:

| Конфигурация | Каналы | Признаки | Filtering | Accuracy | Macro-F1 | Feature vector size |
|---|---:|---|---|---:|---:|---:|
| Full baseline | 24 | basic | raw | 0.9479 | 0.9481 | 96 |

Этот baseline важен как верхняя опорная точка для сравнения с уменьшенными наборами каналов. Дополнительно для medium split есть близкая по смыслу baseline-оценка `24 channels + basic`, где `Macro-F1 = 0.9284`, но для итогового сравнения по качеству ниже более показателен именно full split, так как он использует существенно больше данных.

## 5. Сокращение числа каналов

Для анализа channel reduction использовались `channel_sweep_results.csv`, `channel_sweep_medium_results.csv` и прежде всего `channel_sweep_full_results.csv`. В полном split доступны методы `full`, `ranking` и `greedy` для числа каналов `3, 6, 8, 12, 16, 24`.

Лучшие leakage-safe результаты на полном split:

| Метод | Каналы | Selected channels | Accuracy | Macro-F1 | Feature vector size | Интерпретация |
|---|---:|---|---:|---:|---:|---|
| full | 24 | all | 0.9479 | 0.9481 | 96 | baseline |
| greedy | 16 | `[8, 5, 1, 6, 9, 17, 15, 22, 20, 18, 4, 3, 21, 2, 11, 10]` | 0.9441 | 0.9443 | 64 | лучший reduced result |
| greedy | 12 | `[8, 5, 1, 6, 9, 17, 15, 22, 20, 18, 4, 3]` | 0.9376 | 0.9379 | 48 | сильная компрессия при малой потере качества |
| greedy | 8 | `[8, 5, 1, 6, 9, 17, 15, 22]` | 0.8647 | 0.8641 | 32 | заметная деградация качества |
| ranking | 6 | `[8, 0, 13, 5, 15, 14]` | 0.8476 | 0.8476 | 24 | качество уже существенно ниже baseline |
| ranking | 3 | `[8, 0, 13]` | 0.8042 | 0.8062 | 12 | слишком сильное сжатие для надежного baseline-like режима |

Если измерять потери относительно baseline `Macro-F1 = 0.9481`, получаем:

- `16 channels`: падение всего на `0.0038`;
- `12 channels`: падение на `0.0102`;
- `8 channels`: падение на `0.0840`;
- `6 channels`: падение на `0.1005`;
- `3 channels`: падение на `0.1419`.

Из этих чисел следует практический вывод: диапазон `12-16` каналов действительно выглядит рабочим компромиссом, а переход к `8` и ниже уже меняет качество слишком заметно. Гипотеза о том, что можно почти без потерь уйти в `3-6` каналов, текущими leakage-safe full-scale результатами не подтверждается.

Важно отметить и поведение методов. Для `3` и `6` каналов на полном split ranking оказался лучше greedy, а начиная с `8` и выше greedy дал лучшие итоговые reduced-конфигурации. То есть ranking полезен как простой устойчивый способ первичного ранжирования, но лучший reduced result в практически интересной зоне `12-16` каналов дал именно greedy.

## 6. Сравнение basic и extended TD features

Для сравнения признаков использовались:

- `feature_sweep_results.csv`;
- `feature_sweep_medium_results.csv`;
- `feature_sweep_medium_full_results.csv`;
- `feature_sweep_medium_ranking_results.csv`;
- `repeated_medium_evaluation_results.csv`.

Ниже приведены representative leakage-safe medium результаты:

| Каналы | Feature set | Accuracy | Macro-F1 | Feature vector size | Processing time, ms | Комментарий |
|---:|---|---:|---:|---:|---:|---|
| 24 | basic | 0.9278 | 0.9284 | 96 | 0.2795 | baseline medium |
| 24 | extended_td | 0.9574 | 0.9575 | 264 | 0.2864 | лучшее качество, но в 2.75 раза больше признаков |
| 12 | basic | 0.8734 | 0.8727 | 48 | 0.1524 | ranking source |
| 12 | extended_td | 0.9180 | 0.9178 | 132 | 0.1576 | сильный прирост при умеренном росте времени |
| 12 | basic | 0.8186 | 0.8194 | 48 | 0.1442 | greedy source |
| 12 | extended_td | 0.8787 | 0.8788 | 132 | 0.1476 | заметный выигрыш относительно basic |
| 6 | basic | 0.8182 | 0.8162 | 24 | 0.1742 | ranking source |
| 6 | extended_td | 0.8432 | 0.8425 | 66 | 0.1220 | умеренное улучшение |

Общий эффект extended TD features стабилен:

- для `24` каналов прирост `Macro-F1` составил около `+0.0291`;
- для `12` каналов около `+0.0451` у ranking и `+0.0594` у greedy;
- для `8` каналов около `+0.0344` у ranking и `+0.0565` у greedy;
- для `6` каналов около `+0.0262` у ranking и `+0.0219` у greedy;
- для `3` каналов около `+0.0459` у ranking и `+0.0370` у greedy.

Главный недостаток extended TD features заключается в росте размера признакового вектора: во всех рассмотренных конфигурациях он увеличивается ровно в `2.75` раза относительно basic. При этом рост `processing_time_ms` оказался небольшим по сравнению с выигрышем в качестве. Например, для `24` каналов на medium split время выросло только с `0.2795` до `0.2864` ms, тогда как `Macro-F1` вырос с `0.9284` до `0.9575`.

Следовательно, на текущем этапе ответ на вопрос "стоит ли расширенный набор признаков увеличения размерности?" скорее положительный для offline-качества. Для жестко ограниченного embedded-сценария это решение уже зависит от допустимой размерности и бюджета памяти.

## 7. Raw vs filtered

Сравнение raw и filtered вариантов выполнено в `channel_sweep_filtered_comparison.csv`. Фильтрация включала `notch 50 Hz` и `bandpass 20-450 Hz`.

Representative результаты:

| Каналы | Метод | Raw Macro-F1 | Filtered Macro-F1 | Разница | Вывод |
|---:|---|---:|---:|---:|---|
| 3 | greedy | 0.7448 | 0.7629 | +0.0181 | фильтрация полезна |
| 6 | greedy | 0.8164 | 0.8405 | +0.0241 | фильтрация полезна |
| 8 | greedy | 0.8519 | 0.8501 | -0.0018 | выигрыша нет |
| 12 | greedy | 0.8194 | 0.8184 | -0.0010 | различие несущественно |
| 3 | ranking | 0.6473 | 0.6414 | -0.0059 | стало хуже |
| 6 | ranking | 0.8162 | 0.8085 | -0.0078 | стало хуже |
| 12 | ranking | 0.8727 | 0.8674 | -0.0052 | стало хуже |
| 24 | full | 0.9345 | 0.9325 | -0.0021 | baseline почти не меняется |

Для `16` каналов filtered comparison в этой таблице отсутствует, поэтому для этого числа каналов вывод по фильтрации в отчете не делается.

Итог по фильтрации достаточно простой:

- фильтрация помогает прежде всего для очень компактных greedy-конфигураций (`3` и `6` каналов);
- для ranking и для более широких конфигураций устойчивого улучшения не видно;
- на полном наборе каналов эффект близок к нулю или слегка отрицателен.

Это значит, что raw pipeline можно считать основным режимом для дальнейших сравнений, а filtered mode разумно оставлять как опцию для агрессивно сжатых наборов каналов.

## 8. Стабильность выбора каналов

Стабильность оценивалась в `channel_stability_results.csv` через несколько train/validation разбиений. Для pairwise сравнения использовался Jaccard overlap между выбранными наборами каналов.

Сводка:

| Метод | Каналы | Mean Jaccard | Вывод |
|---|---:|---:|---|
| greedy | 3 | 0.0333 | почти полная нестабильность |
| greedy | 6 | 0.1747 | слабая устойчивость |
| greedy | 8 | 0.2186 | устойчивость ниже средней |
| greedy | 12 | 0.3756 | лучше, но все еще заметно зависит от split |
| ranking | 3 | 0.2167 | лучше greedy, но нестабильно |
| ranking | 6 | 0.5794 | уже умеренно устойчиво |
| ranking | 8 | 0.6963 | хорошая устойчивость |
| ranking | 12 | 0.7429 | наиболее стабильный режим из рассмотренных |

Из результатов видно:

- greedy чаще находит конфигурации с более высоким качеством в practically useful зоне `12-16` каналов, но его конкретный состав каналов заметно зависит от разбиения;
- ranking проигрывает greedy по лучшему качеству на full split в зоне `12-16`, зато дает существенно более стабильные наборы каналов;
- для `3` каналов даже ranking остается недостаточно устойчивым, поэтому такие конфигурации плохо подходят как надежная инженерная рекомендация.

Следовательно, если нужен интерпретируемый и повторяемый список приоритетных каналов, ranking выглядит лучше. Если приоритетом является максимальное качество reduced-конфигурации, лучше использовать greedy, но понимать, что его выбор сильнее зависит от конкретного train/validation split.

## 9. Offline bandit simulation

Результаты offline bandit-симуляции сохранены в `bandit_simulation_results.csv`. В этой постановке bandit не обучается на потоке сырых сигналов, а выбирает готовое действие из заранее рассчитанных офлайн-конфигураций. Награда имела вид:

```text
reward = macro_f1 - alpha * processing_time_ms - beta * channels_count - gamma * feature_vector_size
```

Лучшие действия для разных reward profiles:

| Reward profile | Selected action | Channels | Feature set | Macro-F1 | Reward | Интерпретация |
|---|---|---:|---|---:|---:|---|
| quality_first | `full` | 24 | extended_td | 0.9575 | 0.9170 | максимум качества |
| balanced | `random` | 16 | basic | 0.9317 | 0.8689 | компромисс между качеством и компактностью |
| low_latency | `random` | 16 | basic | 0.9317 | 0.8745 | latency-профиль все равно выбирает 16 каналов |
| compression_first | `random` | 6 | basic | 0.8526 | 0.7851 | при сильном штрафе за размер выбирается компактный набор |

Из этого не следует, что `random` в общем случае лучше greedy или ranking как метод отбора каналов. Здесь bandit выбирает уже готовую action-конфигурацию по функции награды, и при определенных штрафах случайно найденный набор на medium split оказался выгоднее именно по этой функции.

Поэтому bandit в текущем виде нужно трактовать как proof of concept для policy-level выбора конфигурации системы, а не как доказанно лучший адаптивный алгоритм работы с EMG.

## 11. Основные выводы

По совокупности leakage-safe результатов можно сформулировать следующие выводы.

1. Полный baseline на `24` каналах остается сильнейшей базовой конфигурацией с `Macro-F1 = 0.9481` на full split и `Macro-F1 = 0.9284` на medium split для basic features.
2. Сокращение до `16` каналов почти не ухудшает качество: лучший reduced result (`greedy`) уступает baseline всего на `0.0038` по `Macro-F1`.
3. Сокращение до `12` каналов все еще выглядит практически оправданным: потери составляют около `0.0102` по `Macro-F1`, а размер признакового вектора уменьшается с `96` до `48`.
4. Переход к `8` каналам и ниже уже сопровождается заметной деградацией качества; для `6` и `3` каналов потери слишком велики, чтобы считать их baseline-like заменой полному набору.
5. Extended TD features стабильно улучшают качество почти во всех проверенных конфигурациях, но увеличивают размер признакового вектора в `2.75` раза.
6. Greedy обычно дает лучший reduced result в practically useful зоне `12-16` каналов, но ranking заметно стабильнее по составу выбранных каналов.
7. Фильтрация полезна в первую очередь для очень компактных greedy-наборов, а для более широких или ranking/full конфигураций явного преимущества не показывает.
8. Offline bandit подтверждает, что при разных функциях награды можно автоматически выбирать разные operating points системы: от `24 + extended_td` при приоритете качества до `6 + basic` при приоритете компрессии.

## 12. Ограничения исследования

У текущих выводов есть несколько ограничений.

- Основные надежные выводы по сокращению каналов опираются на quick, medium и full split внутри одного датасета, а не на внешнюю кросс-базовую проверку.
- Stability analysis проводился на ограниченном наборе разбиений и отражает относительную, а не абсолютную устойчивость методов.
- Extended TD features оценивались в терминах `processing_time_ms` внутри текущего Python pipeline; это не эквивалентно реальному embedded runtime.
- POC-визуализация является synthetic/schematic representation.
- Offline bandit работает только по уже готовым CSV и не моделирует online adaptation на уровне потока сигнала.

Эти ограничения не отменяют практической ценности результатов, но задают границы интерпретации.

## 13. Текст для введения и постановки задачи

В работе рассматривается упрощение классификационного pipeline для поверхностной электромиографии за счет сокращения числа входных каналов без неприемлемой потери качества распознавания жестов. В качестве базовой модели используется LDA-классификатор с time-domain признаками, вычисляемыми по скользящим окнам для подмножества жестов датасета GRABMyo.

Для корректной оценки такого упрощения необходимо не только сравнить качество моделей при разном числе каналов, но и исключить методологические ошибки в процедуре отбора каналов. Поэтому в работе используется leakage-safe схема разбиения, в которой выбор каналов производится только на training/validation участниках, а test set применяется исключительно для финальной оценки.

Полученные результаты показывают, что уменьшение числа каналов до `12-16` может сохранять высокое качество классификации, тогда как более агрессивное сокращение приводит к заметной деградации. Дополнительно исследуется влияние расширенного набора time-domain признаков, фильтрации сигнала, стабильности выбора каналов и offline-стратегии выбора рабочей конфигурации.

## 14. Направления дальнейшей работы

Логичными следующими шагами выглядят:

- проверка выбранных `12`- и `16`-канальных конфигураций на более строгих межсессионных или межсубъектных сценариях;
- повторный stability analysis на большем числе random splits;
- профилирование feature extraction в условиях, ближе к целевому embedded runtime;
- сравнение greedy/ranking не только по конечному качеству, но и по интерпретируемости каналов относительно анатомической разметки;
- развитие bandit-идеи из offline выбора конфигурации в online adaptive controller;
- развитие GUI и visualization-слоя как демонстрационного интерфейса для pipeline.

## Итог

Текущие leakage-safe результаты подтверждают, что для рассматриваемого EMG pipeline наиболее практичным компромиссом выглядит сокращение до `12-16` каналов. Конфигурации `3-6` каналов пока следует трактовать как исследовательские и слишком слабые для замены полного baseline. Расширенный набор TD-признаков улучшает качество почти во всех проверенных режимах и особенно интересен для сценариев, где допустимо увеличение размерности признаков ради прироста `Macro-F1`.
